# 论文论证框架

## 中心论点

在固定航迹级划分和防泄漏评价协议下，航迹运动特征与 RD 图像提供的是不同粒度、不同物理域的判别证据。将两路证据按航迹对齐并保留各自独立判断，可以系统检验其错误互补性；质量感知门控是否带来增益必须由 rescue/harm 统计和原始分区 Macro-F1 共同决定，而不能由融合结构本身预设。

## 子论点与 CER 链

### 子论点 1：TR 航迹分支是可靠的独立基准

- **证据**：当前项目在固定 F split validation 上复现原项目 B01，232 条航迹的混淆矩阵逐项一致；Accuracy=0.9310345，Macro-F1=0.8694954。
- **推理**：在融合前锁定 TR 分支的输入、标签顺序、标准化和评价协议，可以把后续变化归因于 RD 或融合环节，而不是迁移误差。
- **反向问题**：B01 只包含航迹，不是多模态模型；如果直接称其为多模态基线，会夸大比较结论。
- **处理**：全文统一称为 TR-only B01-compatible 基线。

### 子论点 2：RD 分支提供与航迹不同的判别证据，但性能依赖预处理

- **证据**：RD 文件具有不同列宽和不同 Vr 范围，统一处理必须依据每个文件的 Vr 坐标；R2-900 在固定验证协议下 Accuracy=0.9138、Macro-F1=0.8526。
- **推理**：RD 的输入统一方式本身会改变可用物理信息，不能把列号当作速度坐标，也不能脱离速度范围、重采样和归一化讨论 RD 性能。
- **反向问题**：RD 与 TR 都来自同一雷达观测，不能简单宣称是完全独立传感器。
- **处理**：将其表述为同源观测的不同表征域，并用错误互补性而非“独立传感器”证明融合价值。

### 子论点 3：融合效果取决于错误互补性和门控校准，而非简单叠加

- **证据**：固定 RD 权重 0.2 的验证结果与 TR 基线相同，未观察到相对 TR 的 rescue 或 harm；融合协议要求 RD 帧先聚合到航迹级，并保存 TR、RD、融合三套判断。
- **推理**：若两路在同一航迹上同时出错，融合无法通过平均概率修复；门控还必须使用训练集 OOF 分数，避免验证/测试泄漏。
- **反向问题**：质量门控可能在小样本校准集上过拟合，导致测试集退化。
- **处理**：把门控权重、校准数据来源、测试结果和 rescue/harm 样本同时报告，不以拟合集分数作为泛化结论。

### 子论点 4：Bird/Unknown 是需要类别级分析的主要边界

- **证据**：TR B01 validation 中 Bird→Unknown 4 条、Unknown→Bird 4 条；Unknown F1=0.6896552。RD 归因显示正确 Bird 的速度响应通常更窄，而 Bird→Other 错例响应更宽；Other→Bird 错例表现为较窄、较尖且稳定的响应。
- **推理**：仅报告总体 Accuracy 会掩盖少数类边界；需要结合类别 F1、双向混淆数量和输入归因分组分析。
- **反向问题**：错例数量少，组均值可能不稳定，不能直接推出普适物理规律。
- **处理**：明确将归因结果定义为探索性证据，并保留航迹编号和样本数。

## 逻辑流程

任务背景与已有航迹研究 → 航迹单分支基准可复现 → RD 统一预处理与独立评价 → 同航迹粒度对齐 → 固定融合与质量门控 → rescue/harm 和类别级边界分析 → 讨论融合有效/无效的条件。

## 论证强度

| 论点 | 证据强度 | 结论措辞 |
|---|---|---|
| TR 基线复现可靠 | 强 | “逐航迹一致复现” |
| RD 与 TR 具有不同表征信息 | 中 | “提供不同域证据”，不写“独立传感器” |
| 融合必然提升性能 | 弱/未证实 | 不作预设，报告实际增益或退化 |
| Bird/Unknown 是主要边界 | 中强 | 用混淆矩阵和 F1 支持，保留样本量限制 |
| RD 速度响应宽度是候选判别特征 | 中 | “候选特征/探索性发现”，不写因果规律 |
